## 重试状态

宿主日志已记录 1/5、2/5、3/5 等恢复过程。每次 CLI 自身先进行 HTTP 重试，约三分半后才将失败交给宿主。
宿主恢复继续使用同一个会话 ID，因而重复命中上述确定性故障；五次恢复不能解决该失效绑定。
网关累计请求数包含 CLI 内部重试、宿主恢复以及本次明确标记旧 ID 的隔离实验，不等同于宿主重试次数。

## 恢复方向

保持一般临时错误的有界退避。在判定连续同会话 502 的恢复策略中，可以使用 Claude 原生 fork 能力保留完整对话历史并获得新 ID；宿主必须接收并持久化实际新会话 ID，供后续问题继续使用。不能仅随机改本地 run 记录的 ID，也不能用空白新会话代替完整历史。
故障 ID 的内部绑定最终仍需 keystone 服务端排查，不能把客户端对照实验误写成已确认某个服务端缓存实现有缺陷。
