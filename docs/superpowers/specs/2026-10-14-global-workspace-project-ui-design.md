# 全局工作区与项目空间 UI 设计

日期：2026-10-14
状态：设计已确认，尚未实施
交互原型：`.superpowers/brainstorm/17408-1791968398/content/ide-current-scopes-v5.html`
关联架构：`docs/superpowers/specs/2026-10-14-system-project-workspace-design.md`

## 1. 背景

Cezar 已具备项目注册表、项目作用域 API、项目路由和每任务 Worktree，但当前产品仍保留 boot project 语义：服务启动目录会参与项目身份、默认路由和部分运行时构建。这使用户容易把“启动 Cezar 的目录”误认为当前项目。

本设计采用 IntelliJ IDEA 式心智模型：Cezar 首先是一个全局工作区，项目是用户显式进入的独立上下文。服务从哪个目录启动，不决定首页、当前项目或项目登记。

## 2. 已确认目标

- `/` 永远是全局工作区首页，不自动进入任何项目。
- `cez serve` 不绑定当前启动目录，也不自动注册当前目录。
- 用户从项目选择器显式进入项目，并可随时返回全局工作区。
- 未选择项目时，不展示项目导航，也不能直接创建任务。
- 任务、Worktree、Git、GitHub、TAPD、自动化、技能、工作流和项目设置归属于项目。
- 跨项目仪表盘、全部任务、项目管理、资源限制、Agent 账户和全局设置归属于全局工作区。
- 现有项目能力继续使用，不因 UI 重组而改变业务语义。

## 3. 非目标

- 本设计不创建“默认项目”设置。
- 不把最近访问项目作为 `/` 的自动跳转目标。
- 不允许项目页面通过隐式 boot/default alias 执行项目操作。
- 不在本次 UI 设计中重新定义项目状态存储迁移；该问题由关联架构设计负责。
- 不把项目级自动化、技能或工作流提升为全局能力。

## 4. 作用域模型

```text
全局工作区 /
  ├─ 工作区首页
  ├─ 全部任务
  ├─ 项目管理
  └─ 全局设置
       │
       └─ 选择项目
            ↓
项目空间 /p/:projectId/
  ├─ 项目概览
  ├─ 任务与 Worktrees
  ├─ Git / GitHub
  ├─ TAPD
  ├─ 自动化
  ├─ 技能
  ├─ 工作流
  └─ 项目设置
```

作用域是路由状态，不是进程级的可变“当前项目”。多个浏览器标签可以同时打开不同项目；切换一个标签中的项目不能改变其他标签或正在运行的任务。

## 5. 信息架构

### 5.1 常驻外壳

左侧栏顶部由品牌、工作上下文选择器和新建任务按钮组成。全局导航始终可见；项目导航只在项目路由下出现。

工作上下文选择器在全局状态显示：

```text
◈ 全局工作区
  未选择项目
```

展开后第一项固定为“全局工作区”，其后列出已注册项目，底部提供“注册项目”。选择全局工作区等价于进入 `/`；选择项目等价于进入 `/p/:projectId/`。

### 5.2 全局工作区首页

首页明确显示“固定首页，不绑定命令启动目录”，包含：

- 跨项目的待处理、运行中、已完成和失败任务指标。
- 全局并行槽位与资源使用情况。
- 已注册项目的运行状态、待评审任务和 Git 主分支摘要。
- 当前全局配置摘要。
- 明确的“选择项目”入口。

未选择项目时，“新建任务”按钮禁用，文案为“先选择项目再新建任务”。这比弹出一个隐式默认项目更能表达任务必须有项目归属。

### 5.3 项目空间

进入项目后：

- 选择器显示项目名称与规范化路径。
- “新建任务”启用，任务自动归属于路由中的 `projectId`。
- 左侧出现完整项目导航。
- 主内容顶部显示“返回全局工作区”。
- 项目概览汇总 Worktree、Git、GitHub、TAPD、自动化、技能和工作流状态。

返回全局工作区时，UI 必须同时：

1. 导航到 `/`。
2. 隐藏项目导航。
3. 清除页面级项目选择、草稿和详情状态。
4. 禁用项目任务创建入口。
5. 取消当前页面的项目级实时订阅，但不停止后台任务。

## 6. 配置归属

| 全局配置 | 项目配置 |
| --- | --- |
| 项目注册表 | Git 仓库及远端 |
| 全局资源上限 | GitHub/Forge 关联 |
| Agent 账户 | TAPD/Tracker 连接 |
| Agent 全局默认值 | 项目 Agent 覆盖 |
| 全局 UI 偏好 | 自动化 |
| 通知及机器级能力 | 技能目录与来源 |
| 跨项目任务视图 | 工作流 YAML |
|  | 项目 Secrets |
|  | 任务、运行记录与 Worktrees |

设置页面必须通过标题、面包屑和字段说明展示其作用域。项目设置中的继承项应同时显示生效值与来源，并提供“恢复全局默认”。

## 7. 路由设计

| 路由 | 作用域 | 行为 |
| --- | --- | --- |
| `/` | 全局 | 固定工作区首页 |
| `/tasks` | 全局 | 跨项目任务列表 |
| `/projects` | 全局 | 注册、检查和移除项目 |
| `/settings/global` | 全局 | 机器及工作区设置 |
| `/p/:projectId/` | 项目 | 项目概览 |
| `/p/:projectId/tasks` | 项目 | 项目任务与 Worktrees |
| `/p/:projectId/git` | 项目 | Git 与 Forge |
| `/p/:projectId/tracker` | 项目 | TAPD/Tracker |
| `/p/:projectId/automations` | 项目 | 项目自动化 |
| `/p/:projectId/skills` | 项目 | 项目技能 |
| `/p/:projectId/workflows` | 项目 | 项目工作流 |
| `/p/:projectId/settings` | 项目 | 项目配置与覆盖 |

`projectId` 必须来自注册表。不存在的 ID 返回项目不存在状态；目录丢失的项目显示可恢复的 missing 状态，而不是跳回其他项目。

旧的平铺页面可以在目标唯一可确定时跳转到显式项目 URL；不能根据服务启动目录猜测目标。`/p/default` 仅在兼容期存在，不能出现在新 UI 生成的链接中。

## 8. 后端适配

### 8.1 系统启动

`cez serve` 只创建 SystemRuntime：加载工作区配置、项目注册表、Agent 账户、资源调度器和全局事件服务。零项目必须是正常状态。

启动阶段不得：

- 以 `process.cwd()` 创建项目 Store 或 RunManager。
- 自动把当前目录加入项目注册表。
- 为启动目录生成未注册 boot project。
- 让无作用域 API 静默操作启动目录。

### 8.2 项目上下文

所有项目通过同一 ProjectContext/ProjectRuntime 工厂按 `projectId` 获取，不再区分 boot context 和其他项目 context。项目上下文可按需构建；已启用自动化或存在恢复任务的项目由后台协调器主动构建。

项目上下文的创建、缓存、销毁和错误状态由后端管理，不能由“用户当前浏览哪个项目”决定任务是否继续执行。

### 8.3 API 边界

- 全局 API 使用 `/api/v1/...`，不接受项目默认值。
- 项目 API 统一使用 `/api/v1/p/:projectId/...`。
- 创建任务请求必须带可验证的项目作用域。
- 契约继续在 `packages/contract` 使用 Zod 定义，由类型推导。
- Hono 路由继续通过 family builder 链式注册，并用 middleware 验证参数、查询和请求体。
- 事件必须带真实 `projectId`；前端不得把 `default` 转换成某个缓存键。

## 9. 前端状态与数据流

- URL 是当前页面项目作用域的唯一事实来源。
- 全局 query key 不包含项目 ID；项目 query key 必须包含 `projectId`，必要时包含 binding revision。
- 项目切换必须让项目级页面完整卸载，避免新建任务草稿、TAPD 选择、diff、过滤器和请求响应串到新项目。
- 切换项目不取消已提交任务，也不改变任务捕获的配置快照。
- 全局任务列表的每一行明确显示所属项目；点击后进入对应项目详情 URL。
- SSE/WS 的项目事件按 `projectId` 路由到对应缓存；离开项目页面只取消视图订阅，不关闭系统级事件通道。

## 10. 关键交互状态

### 零项目

首页保留全局导航和设置能力，指标显示空状态，主操作为“注册项目”。不创建临时项目。

### 项目目录丢失

选择器保留项目条目并显示“目录不可用”。进入后提供重新定位或移除绑定操作；不自动创建目录，也不把请求转发到其他项目。

### 项目加载失败

项目外壳继续显示项目身份和返回入口。错误区域说明失败原因并提供重试；全局工作区仍可使用。

### 项目被移除

如果当前标签正在查看被移除项目，显示“项目已从工作区移除”，提供返回全局工作区；不自动进入另一个项目。

### 全局新建任务

第一版保持禁用按钮，不在全局页面直接创建任务。以后如需快捷入口，应先显式选择项目，再进入该项目的新建任务页，不能保存全局任务草稿。

## 11. 视觉规范

- 视觉语言延续现有 Cezar：浅色、低噪声、紧凑的开发工具密度。
- 工作上下文选择器是唯一强调作用域的主要控件。
- 全局使用紫色语义标识，项目使用绿色语义标识；颜色仅辅助，始终配合文本 `Global`/`Project`。
- 全局导航和项目导航用分组与分隔线编码层级，不依赖图标猜测。
- 路径使用等宽字体并允许截断；项目名称保持易读的正文样式。
- 禁用的新建任务按钮必须解释原因，不能只降低透明度。
- 键盘焦点清晰；项目选择器支持方向键、Enter、Escape 和项目名搜索。
- 移动窄屏下侧栏变为抽屉，但全局/项目层级和返回动作保持一致。

## 12. 兼容与迁移

- 保留旧项目 URL 的定向兼容，但所有新链接只生成显式 `projectId` URL。
- 原有浏览器“最后位置”可以用于提示最近项目，不得改变 `/` 的固定首页语义。
- 升级后首次启动不得把启动目录新增为项目。
- CLI `cez run` 仍可将当前目录作为明确的命令目标；这不等价于 `cez serve` 的全局工作区行为。
- 桌面应用、服务安装和 Vite 开发入口必须与 `serve` 保持相同的无 boot project 语义。

## 13. 验收标准

- 从任意两个目录启动同一 Cezar 实例，访问 `/` 得到相同全局工作区，项目注册表不发生变化。
- 工作区可以在没有任何项目时启动和使用全局设置。
- 未选项目时项目导航不可见，新建任务不可用。
- 选择项目 A 后，所有项目请求只访问 A 的显式作用域。
- 从项目 A 返回首页后，项目导航、草稿和项目订阅被清理，A 的后台任务继续运行。
- 可在两个浏览器标签同时打开项目 A 和 B，任务、配置、事件和缓存互不串用。
- 全局任务列表能汇总多个项目，并在每条任务上显示正确项目。
- 项目级 Git、TAPD、自动化、技能和工作流保持现有能力。
- 旧链接不会因服务启动目录不同而落到不同项目。
- 项目不存在、目录丢失和运行时失败均有明确状态，不自动回退到其他项目。
- 路由契约、typed client、项目隔离测试和真实浏览器交互测试通过。

## 14. 实施边界

推荐按以下顺序实施：

1. 移除 boot project 对 SystemRuntime、契约和项目上下文的依赖。
2. 建立固定全局路由和显式项目 API。
3. 重构前端 scope、query key 与事件路由。
4. 实现双层导航、选择器、项目概览和异常状态。
5. 完成兼容迁移与端到端验证。

这些步骤构成一个完整行为变更，不能只发布 UI 跳转而保留后端启动目录默认项目，否则界面表达与实际执行作用域会不一致。

## 15. 设计结论

Cezar 的顶层对象是全局工作区，不是启动目录；项目是被工作区显式登记并按路由进入的独立执行上下文。UI、API、缓存、事件和后台生命周期必须共同遵守这一边界。该模型既符合 IntelliJ IDEA 的项目选择体验，也消除了当前 boot project 带来的隐式数据归属。
